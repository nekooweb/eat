## 目标

公开来源采集 → 原始记录留档 → Place ID 关联及字段校验 → 本地 SQLite 主库 → 单一网页快照。

全量目录、已取得资料、已验证资料和推荐可用性分别统计。2,804 个目录条目必须全部保留；缺失、冲突和来源不可访问都不是删除目录的理由。

## 授权与边界

项目负责人已明确要求将获得授权的 Google Place ID 关联业务资料持久化，并确认本地 SQLite 主库方向。新设计不再沿用「Google 关联显示字段一律不得保存」的项目级规则。

保存授权、实际取得数据的入口和公开发布范围是不同事项。原始记录应保存来源、取得方式、授权依据与时间；不保存 API Key、Cookie、会话令牌和无关个人信息。不能把业务字段的持久化授权解释成重启旧付费接口或公开整份原始响应的授权。

代码及文档通过 GitHub 插件修改，不克隆仓库到本地编辑。本地后续仅保存主数据库、原始记录及备份。GitHub Actions 不具备直接读取个人电脑主库的能力；经过校验的导出必须显式交接到 GitHub。
