# 2026-09-08 — Remove repetitive template recommendations from public dish display

## Problem found

The previous `relaxed-zh-v2` runtime layer intentionally filled missing dish data with approximate Chinese suggestions inferred from broad cuisine labels, restaurant names, dish keywords, and brand rules. This improved display coverage, but it also created repeated fixed pairs that looked like restaurant-specific recommendations even though they were only category-level approximations.

Artifact-level repetition before this correction included:

- `烤鲭鱼 · 日式炸鸡`: 133 restaurants
- `手冲咖啡 · 三明治`: 117 restaurants
- `烤鸡串 · 日式炸鸡`: 101 restaurants
- `意大利面 · 披萨`: 57 restaurants
- `炒饭 · 煎饺`: 51 restaurants
- `烤肉拼盘 · 牛舌`: 20 restaurants

The largest causes were broad rules such as `broad-japanese`, `broad-izakaya`, `cuisine-cafe`, `cuisine-italian`, and `cuisine-chinese`. These rules were useful as approximate cuisine hints, but they were not sufficiently restaurant-specific to justify the public label `推荐菜`.

## New policy

Policy: `strict-source-zh-v1`

Public recommendation semantics are now accuracy-first:

1. Do not synthesize `recommendedDishes` from broad cuisine labels.
2. Do not synthesize `recommendedDishes` from restaurant-name keywords.
3. Do not synthesize `recommendedDishes` from brand templates.
4. Do not use generic fallback dishes.
5. Keep only already-retained recommendation / featured-dish evidence or curated canonical dish data.
6. Sanitize displayed dish names to Chinese and remove duplicate items within a restaurant.
7. If no retained dish evidence exists, hide the recommendation/featured-dish line instead of filling it with a plausible template.
8. Remove all approximate runtime metadata from public rows.

Approximate inference can still be useful during internal research or enrichment prioritization, but it is no longer materialized into the public `推荐菜` field.

## Evidence caveat

The retained 185 recommendation rows are source/curation-backed rows already present in the repository's persisted evidence layers; they are not 185 newly crawled recommendations from this run. Current detail-evidence reporting includes a smaller fresh-crawl subset, while older retained evidence remains available where it passed existing binding/provenance rules. The important behavioral change in this correction is that **zero additional recommendation rows are invented at runtime**.

## CI / safety

The blocking dish audit now requires:

- `dishReviewPolicy = strict-source-zh-v1`
- `approximateChineseDishRows = 0`
- `approximateRecommendationsAllowed = false`
- `genericFallbackAllowed = false`
- no legacy approximate metadata on public rows
- Chinese-only recommendation display strings
- duplicate-pair statistics emitted on every build for ongoing review

The zero-paid-data-API policy remains unchanged and passed in the same build path:

- paid data API hits: `0`
- map: Leaflet + OpenStreetMap
- Google Maps: external navigation only
