## Source-shard compatibility fix

The first Pass 3 draft required the existing official row to already be present in `window.RESTAURANTS`. The canonical combined builder satisfies that load order, but `coverage_report.mjs` evaluates source shards individually. The standalone report therefore threw `Pass3 official source row missing` even though the canonical build was valid.

The final shard now supports both contexts:

- canonical combined loader: augment the already-existing exact-Place-ID official row;
- standalone report loader: create a minimal self-contained official source row for report inspection.

The combined loader still preserves the one-official-provider-row-per-Place-ID invariant.

## CI hardening

The incident exposed a second issue: the Pages coverage step piped report commands to `tee` without `pipefail`. A failing Node report could therefore be masked by successful `tee` exit status and the workflow could appear green.

`.github/workflows/pages.yml` now runs:

```bash
set -o pipefail
```

before coverage/report pipelines. A failure in `coverage_report.mjs`, `source_queue.mjs`, `build_enrichment_queue.mjs`, `dish_gap_report.mjs` or `audit_area1_identity_coverage.mjs` now fails the workflow as intended.
